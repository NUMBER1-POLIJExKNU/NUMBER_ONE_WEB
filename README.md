# NUMBER ONE 포트폴리오 랜딩페이지

NIA 성과보고회 발표 마지막에 띄울 **QR코드의 목적지**입니다.
발표를 막 본 심사위원이 폰으로 스캔해서 들어옵니다.

페이지에 쓰인 모든 수치와 링크의 단일 출처는 [`src/data/evidence.ts`](./src/data/evidence.ts)입니다.
새 수치를 넣을 일이 생기면 먼저 그 파일에 근거와 함께 추가하세요.

> 설계 근거와 사실 검증 내역을 정리한 내부 문서(`implementation_plan.md`)는
> 저장소에 포함하지 않습니다. 팀 공유 드라이브를 참고하세요.

---

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 폰트 서브셋 + OG 생성 + 타입체크 + 빌드
npm run preview    # 빌드 결과 확인
```

`public/fonts/`와 `public/og.png`는 **빌드가 생성**합니다. 저장소에 커밋하지 마세요.

## 팀이 채워야 할 것

### 1. 팀원 소개와 사진

[`src/data/team.ts`](./src/data/team.ts)를 엽니다. 각 팀원의 `bio`와 `photo`가 지금 `null`입니다.

```ts
{ name: "Rama", legalName: null, role: "PL", bio: null, photo: null },
```

이렇게 채웁니다:

```ts
{
  name: "Rama",
  legalName: "Muchamad Lucky Ramadhan",  // 본인 확인 + 공개 동의를 받은 경우에만
  role: "PL",
  bio: "일정을 잡고 양국 회의를 진행했습니다.",
  photo: "rama.jpg",                      // public/photos/rama.jpg 로 넣으세요
},
```

- `photo`는 `public/photos/` 기준 파일명입니다. 정사각형에 가깝게 잘라서 넣으세요.
- `bio`나 `photo`가 `null`이면 카드에서 **자동으로 생략**됩니다. 일부만 채워도 깨지지 않습니다.
- `legalName`은 **본인에게 확인받고 공개 동의를 받은 뒤에만** 채우세요. git 커밋 이름과 닉네임의 대응은 아직 확정되지 않았습니다.

### 2. 활동 사진

지금 페이지에 실제 사진이 **한 장도 없습니다**. 이게 가장 큰 약점입니다.
필요한 최소 구성:

- 단체 사진 1장
- 활동 장면 3~5장 (교육, 문화교류, 현장)
- 하드웨어 1장 (센서·아두이노 장비)

받는 대로 `public/photos/`에 넣고 "현장에서" 섹션에 배치하면 됩니다.

> **주의**: 활동 장면을 AI로 생성해서 채우지 마세요. 공모전이 활동 성실도를 심사하는데,
> 생성 이미지와 실제 기록이 섞이면 문제가 됩니다. AI 생성물은 분위기컷·타이틀 배경에만 쓰세요.

### 3. 문구를 고칠 때

[`src/i18n/`](./src/i18n)의 `ko.json` / `en.json` / `id.json` 셋을 **같이** 고쳐야 합니다.
키가 없으면 화면에 키 이름이 그대로 나옵니다.

한국어 문구에 **새로운 글자**를 쓴 경우 반드시 `npm run build`(또는 `npm run fonts`)를
다시 돌리세요. 폰트가 실제 쓰는 글자로만 서브셋되어 있어서, 서브셋에 없는 글자는
픽셀 폰트가 아닌 시스템 폰트로 떨어집니다.

## 사실 관계 규칙

페이지에 올린 수치는 전부 디스크·git 로그·라이브 API로 직접 확인한 값입니다.
확인되지 않은 값은 넣지 마세요. 특히 자주 실수하는 것들:

- **수혜자 4,440명은 쓰지 마세요.** KNU 파견단 전체 수치라 9명 팀에 귀속시킬 수 없습니다.
- **센서는 과거형으로.** 2026-08-20 이후 하드웨어가 꺼져 있습니다.
- **모델 정확도 수치 금지.** 평가셋이 없습니다.
- **앱은 2개국어(id/en)입니다.** 3개국어인 건 이 페이지입니다.

## 배포와 QR

1. Vercel에 연결하고 배포 (`vercel.json` 준비되어 있습니다)
2. 배포 URL로 QR코드 생성 → 발표 마지막 슬라이드에 삽입
3. **발표 전에 실제 폰으로 스캔 테스트**를 꼭 하세요. 발표장 회선을 가정해 4G에서도 확인합니다.
4. 배포 도메인이 정해지면 `public/robots.txt`의 Sitemap 줄을 절대 URL로 채우세요.

발표 당일 아침에 확인할 것:

- 페이지가 열리는지
- 히어로의 라이브 링크 3개(웹앱 / 모바일 / GitHub)가 살아 있는지

라이브 링크가 죽으면 페이지의 핵심 주장("아직 온라인")이 무너집니다.
